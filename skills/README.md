# Skills in ADDIE order

Read this index in workflow order. Folder names remain stable for skill discovery and existing references; an alphabetical file explorer does not represent execution order. ADDIE organizes the work, with iteration across stages rather than a one-way handoff.

## 1. Analysis

1. [PDF source preparation](course-pdf-source/SKILL.md) — when the input is a PDF, prepare page-referenced Markdown without inventing missing content. This is an optional source utility, not a training decision.
2. [Needs and performance analysis](course-needs-analysis/SKILL.md) — establish business goals, evidence, learner/environment conditions, causes, and training/non-training decisions.
3. [SME workflow and content analysis](course-sme-analysis/SKILL.md) — after training/combined intervention confirmation, deepen workflow decisions, mistakes, exceptions, and content selection. New evidence can reopen diagnosis.

## 2. Design

4. [Learning objectives, course map, and instructional strategy](course-learning-design/SKILL.md) — derive feasible objectives and the learning sequence from analysis and confirmed scope.
5. [Assessment design](course-assessment-design/SKILL.md) — confirm evidence requirements and item counts/formats, then draft aligned questions, tasks, feedback, and rubrics alongside practice design.
6. [Visual and multimedia design](course-visual-design/SKILL.md) — establish purposeful layouts, media, representative previews, and reusable visual conventions. This skill also supports implementation review during Development.
7. [Storyboard](course-storyboard/SKILL.md) — integrate the approved design into detailed Rise lesson/blocks or Storyline slides for ID review and revision before production. Visual previews and storyboard may iterate together.

## 3. Development

Use the approved storyboard to generate component specifications, render reusable interactions, and verify built behavior. Visual-design and quality-review skills support this stage. A production interaction-building skill/renderer is not yet implemented; see [interactive architecture](../docs/interactive-content-architecture.md). Do not create a placeholder skill merely to fill the stage.

## 4. Implementation

Package and embed the approved interaction, verify the actual host, provide installation instructions, and configure learner access/tracking. These capabilities remain planned; there is no dedicated implementation skill yet. See [delivery and tracking](../docs/evaluation-and-tracking.md).

## 5. Evaluation — also throughout the workflow

8. [Cross-stage quality review](course-quality-review/SKILL.md) — inspect evidence, alignment, and gate readiness during Analysis, Design, and Development as well as delivery. QA does not by itself measure learning or business impact.

Plan Kirkpatrick Levels 4 → 3 → 2 → 1 during Analysis/Design, then collect evidence at the appropriate times. Learner pilots, workplace follow-up, and business-result evaluation are distinct from artifact QA. The evaluation plan is documented; an automated outcome-evaluation service is not implemented.

## Execution status

This is navigation and responsibility mapping, not an executable agent router. The app currently uses deterministic mock generation and review/version functions. See the [roadmap](../docs/roadmap.md) for integration priorities. Preserve actual approval gates and source references when iterating across stages.
